## Phase 1 — DINOv2 真权重接入

> 2026-11-04：原 DINOv3 方案的 gated 权重申请被 Meta 拒绝（实测全部变体 403、
> "rejected by the repo's authors"），全仓切换到公开免审批的 DINOv2。同属 DINO 家族，
> "中后层 CLS→patch 注意力 ≈ 对象级分割"的用法不变；patch 16→14，且无 register token。

- [x] 首次 `--dinov2` 跑通（OBS 虚拟摄像头 + CPU），Phase 1 核对项结果：
  - patch 14：224/14=16、518/14=37 均整除（原 vits16 的 518 不整除问题不复存在）
  - prefix 切片偏移 = 1（DINOv2 无 register token，`num_prefix_tokens` 缺省路径恰好正确）
  - 层区间 [7, 11)（12 层 × 0.6、末层丢弃）热图有结构：屏幕场景热区落在文字/控件上
    （`scripts/check_backend.py` 落盘"裁切帧 | 热图叠加"并排图人工判读）
  - transformers 5.x 默认 SDPA 不物化注意力权重，必须 `attn_implementation="eager"`
    （已固化在 `dinov2_backend.py`，否则 `output_attentions=True` 拿到空 attentions）
- [x] 性能：CPU 224² 实测 ~18 fps，满足 10fps 热图率（本机无 NVIDIA 卡，不做 CUDA 路径）
- [x] 热图信号定案（2026-11-04/05 同帧 A/B + 用户真素材判读，`scripts/compare_heatmaps.py`）：
      **末层 CLS 注意力**（`layer_start_frac=0.92`）最优，中后层次之；PCA 前景图与
      feat-norm **不可行**（弃用）；registers 变体无收益；更大模型（base）暂无必要。
      后处理：平滑取核尺寸语义（sigma 语义经 OpenCV 3σ 自动核会抹平主体尖角；现默认
      224² 不模糊、518²→3×3）；`norm_floor_pct` 背景平台归零为可选项（默认关，见下条审查）
- [x] TokenCut-lite NCut 判读（2026-11-05，用户真素材）：稳定比主体多纳入一部分背景，
      **末层注意力@518² 胜出**——当时不集成 backend（2026-11-06 修订：以主色世界
      掩膜形态集成，见下条）。ncut 行保留在 compare 工具供 full TokenCut（含 CRF
      精修）复查
- [x] 主色世界掩膜集成 NCut 谱分割（2026-11-06）：观感反馈"高注意力≠前景/散/
      超纳入"→ compare 工具扩诊断行（headmax/k3/掩膜/闭运算）+ 新建时域稳定性工具
      `heatmap_stability.py`（掩膜帧间 IoU + 占比）+ 真素材 5 图判读：注意力焦掩膜
      占画面 54%（超纳入坐实）、NCut 4/5 最佳（唯一败因 = 极性中心先验把离中心主体
      翻反——**禁用中心先验，极性改注意力粗质量对齐**）。集成形态：一次前向双图
      （注意力 → 展示/调制，NCut 世界图 → 仅主色路掩膜；`attention.ncut_color`
      默认开，`--no-ncut-color` 回退，mock 恒等注意力；`perception/ncut.py` 单源
      实现后端与诊断脚本共用）。遗留：近静止素材 IoU 未测出差异，**动态素材时域
      稳定性待 OBS 真机验证**；此前"ncut 不稳"反例图已遗失
      极性 v3（同日，新反例截图 1259：文本/涂鸦密集背景把注意力锚带偏 r=0.51 自信
      判反）——6 图 × 2 分辨率锚记分：度数锚 |r|>0.5 时最稳（背景=同质大面积=高
      连通，Fiedler 对度数定向是谱聚类惯例），度数弱时紧凑度锚接手；级联规则在
      **生产尺度 224 上 6/6 全对**，注意力锚与中心先验先后退役。已知边界：dog@518
      一例各锚皆不可分——跨尺度分割几何不同，按侧锚定原理上难两全（v2 在该例
      同错，非回归；518 上展示机启用 ncut 前需复核）。阈值区间 (0.44, 0.59)
      取 0.5——样本量小、裕度不厚，新场景极性可疑先跑 compare 工具
- [x] `norm_floor_pct` 分位归零审查（2026-11-05）：无直接论文依据（LOST 谱系的背景

## Phase 2 — 打分器细化（结合 Itti & Koch 2001）

论文在仓库根：`Itti_Koch_2001.pdf`。

- [x] 机制映射落地（v1 打分器）：center-surround/空间竞争 → 簇对比度项（近似：
      全局色彩显著性，无空间结构）；WTA → 迟滞选主（注视稳定性时序类似物，
      IOR 方向相反未采用）（`hysteresis_margin`/`hysteresis_dist`）
- [x] 簇切换迟滞：挑战簇优势不足 margin 时保持在位主色，抑制"主色闪烁"
- [x] `ColorStabilizer` 大跳变重置（`jump_reset_dist`：换景直接置入，不爬中间色相）
- [x] 置信度 = 主色支配度（胜者得分占全簇总分），进 `FrameResult`，供灯带淡入淡出
- [x] 主色闪烁治理（2026-11-04 机制诊断 + 第一批落地）：
  - 机制链：每轮重抽样重聚类 → 簇集合微抖 → 迟滞只护 0.12 Lab 内近色、远距竞争
    主色裸奔 → 赢家互换 RGB 距离 >60 触发 jump_reset 置入 → τ≈2s 的 EMA 失效 →
    10Hz 全幅闪烁（静态多彩素材必现）
  - 已落地：warm-start 簇心延续（簇集合时域连贯）+ 抽样预算 8000→12000（多彩场景
    统计不稳）+ 调制改双阈值 ramp（观感问题，非闪烁主因）+ λ 0.75→3.0（实测反馈
    焦点/氛围趋同，w∈[1,1.75] 时质量项碾压注意力信号）
  - 待真素材实测后启用：jump_reset 持续性门槛（连续 N 轮超阈值才置入，防闪 C）、
    hysteresis_margin 0.15→0.3（防闪 D 剩余项）
- [x] 主色加权 ramp 化（2026-11-05 背景主导修复）：热图判读正常但焦点色仍被背景
  主导——旧式 w = 1+λ·A 给背景保底权重 1，加权质量 ∝ 面积×权重，大面积背景碾压
  主体，λ 无论多大都排不掉（该缺陷也是此前"焦点/氛围趋同"的根源，λ 只是止痛）。
  权重改为与展示路同形的 ramp（A<lo 记 0、A≥hi 记 1、中间线性，`utils/ramp.py`
  两路共用同一实现），零权重像素抽样前剔除（预算只花在本世界像素）；λ 退役，
  分离杠杆改为 `weight_lo/weight_hi`（0.2/0.8）
- [x] 打分器调参（2026-11-05 实测反馈）：①彩度系数 (0.55+0.45c)→(0.45+0.55c)——
  鲜艳度影响力略调高，灰→满彩最大分差 1.8→2.2 倍；②迟滞动量化——有效保护门槛
  = margin×动量，动量连胜攒（约 5 帧满）、换景乘性泄放（×0.6/帧），margin 默认
  0.15→0.10：旧式从第 2 帧起恒享全额门槛（起选错误会一直锁着、真换景后释放慢），
  动量化后起选/换景初期几乎无保护、静态场景仍全额防同屏闪烁；③（2026-11-06 复盘）
  泄放原只挂"赢家换人"，但门槛恰恰阻止换人——满动量下小优势挑战者永无出头之日
  （稳态自锁），补"被压制挑战者慢泄 ×0.85"（持续 3% 优势 ~0.9s 夺主，合成状态机
  三场景模拟定案：平局噪声不交替、小优势必夺主、固有偏差即随）；参考色 = 赢家
  Lab 的 MoCo 式动量更新（慢 EMA）
- [x] 聚类打分两处精化（2026-11-06 实测反馈）：①"类数偏多" → 近邻簇心合并——
      K 固定保 warm-start，簇心距离 < merge_dist（默认 0.10）并族（贪心合并、族
      均值重算距离防链式误并），同色系场景自动 2-3 族、真多彩不丢分辨率，优于
      静态砍 K；②"贴背景主色更难当焦点主色" → 对比度基准从全帧均色（mush 近似，
      此前并无真正对背景主色的项）换成**上一帧氛围主色**——Itti & Koch 2001
      center-surround 的忠实映射（surround 即背景），保护色解释同型。单向接线
      （氛围侧不接焦点参照）避免双实例互推反馈环，顺带治焦点/氛围趋同。设计
      取向：换基准、不堆项，打分公式仍是四项
- [x] 抽样预算自适应（2026-11-06）：用户质疑"先抽像素后加权会互相入侵"——复核：
      零权重剔除 2026-11-05 已在预算抽样之前落地（背景像素到不了 K-Means），真缺陷
      在其上一层——网格步长按全帧面积定，小主体样本数 ∝ 面积占比，1080p 下 5%
      主体只得 ~600 样本（预算的 5%），其余漏给零权重背景格点（饥饿而非入侵）。
      改为全分辨率掩膜（w>0 ⟺ A>lo，一次比较）+ 本世界自适应密度抽样（≤预算全取、
      超预算按 n_world 定步长交掩膜 ≈ 预算，1080p 实测双实例 ~42ms/轮）。用户备选
      "按权重全量排序取头尾"否决：排名截取 = 分位门控，比例固定不适配主体面积
      （同 norm_floor_pct 否决理由），且丢带内线性语义
- [ ] 打分权重精调（对比度/彩度/紧凑度的系数）依赖真素材人眼评估反馈
