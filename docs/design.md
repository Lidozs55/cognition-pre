# 系统设计

> **一句话**：用一个零标注的自监督视觉模型（DINOv2）实时算出"你在看哪"，据此把画面拆成
> 两个世界——焦点区和氛围区——各自实时提取一个主色，同时输出两路"看得见注意力"的调制视频。

```
OBS 虚拟摄像头（任意片源，30 fps）
        │
        ▼
  中心方形裁切 ──► 裁切帧（原分辨率，读色基准）
        │
        ▼
  缩放到模型尺寸（518² 或 224²）
        │
        ▼
  DINOv2-S 推理（10 fps，一次前向双图）──► 注意力 A(x)∈[0,1]（上采样回裁切坐标）
        │                                  世界图 S(x)=NCut 谱分割（仅主色路）
        ├──────────────────────────────┐
        ▼                              ▼
【主色计算，10 Hz】               【双流调制，全帧率】
  焦点色: 原图 × w=ramp(S)           焦点流: 低注意力区压暗（A）
  氛围色: 原图 × w=ramp(1−S)         氛围流: 高注意力区压暗（1−A）
        │                              │
        ▼                              ▼
  加权聚类 + 打分              视频输出（纯展示，
        │                          不进任何计算）
        ▼
  焦点色 + 氛围色（10fps 数据输出）
```

## 设计总原则

1. **定位与读色分离**：注意力/热图只决定"谁赢"，颜色永远从原图读。
2. **展示与计算分离**：调制视频给人看，加权聚类管出数。

## 模块说明

### M1 输入采集（OBS 虚拟摄像头）

OBS 场景里放视频文件/屏幕捕获/直播流，管线以普通摄像头方式打开虚拟设备取帧。
虚拟摄像头编码端（MJPEG/色度抽样）会带来一次轻微软化，对大面积主色可忽略。
**铁律：所有颜色统计在解码后的 RGB 上做。**

- 代码：`input/frame_source.py`（另有 `test:*` 合成源，无 OBS 也能联调）。

### M2 预处理（裁切+缩放）

中心方形裁切（边长 = min(H,W)），产出两份：裁切帧（原分辨率，作全管线读色坐标系基准）
和缩放帧（518² 或 224²，喂 ViT）。

已知代价：16:9 全景镜头两侧背景被裁，氛围色素材变少——Phase 0 用全景图专项验证，
失真严重则启用备选方案（全画幅可变分辨率输入，DINOv2 原生支持）。

- 代码：`preprocess.py`。

### M3 感知（DINOv2 热图）

DINOv2-S（22M 参数，patch 14）冻结直用，零训练。热图取**末层** CLS→patch 自注意力的多头平均
（DINO 家族招牌特性：注意力 ≈ 对象级分割；层选择即官方 DINO 配方）。层选择经同帧 A/B
（`scripts/compare_heatmaps.py`）定案：末层最干净；PCA 前景图与 feat-norm 信号判**不可行**
（真素材人眼判读），registers 变体无收益，更大模型（base）暂无必要。候选增强：TokenCut
NCut（CVPR 2022，DINO patch 特征归一化割）已在对照工具中 A/B。

后处理（见 perception/base.py）：轻度高斯平滑（`smooth_frac` 核尺寸语义——16 网格
3×3、37 网格 5×5；**勿改回 sigma 语义**，OpenCV 按 3σ 自动核、sigma=1 即 7×7，用户
实测把主体尖角抹平）→ 原始值域 clip 掉前 5% 极值（防"注意力沉降"孤斑；截断线落在
背景平台上时退保唯一信号）→ 可选**背景平台抑制**（`norm_floor_pct`：该分位的值归零，
治背景高注意力泄漏——无直接论文依据且假设主体 <50% 画面，**默认关闭**）→
双线性上采样到裁切坐标。频率约 10 fps（可调参数），中间帧复用最近热图。信号对照
工具：`scripts/compare_heatmaps.py`（层间 A/B + 诊断行）；时域稳定性
`scripts/heatmap_stability.py`（掩膜帧间 IoU + 占比）。

**主色世界图 S(x)**（2026-11-06 集成）：同一前向还产出世界图 = NCut 谱分割
（TokenCut-lite 核心，`perception/ncut.py`，主色路后端与诊断脚本单源共用；224² 的
eigh 仅毫秒级）。背景：真素材判读注意力散斑、焦世界掩膜超纳入（占画面 54%），
谱分割 5 图 4 胜；且 ImageNet 域外素材（动漫/风光）注意力头退化更甚而特征几何仍稳
——恰好论证"结构读特征、展示看注意力"。**极性 = 度数/紧凑度级联**（特征向量符号
歧义；中心先验翻反离中心主体、注意力锚被文本密集背景带偏——两版先后被真素材反例
否决，判读史见 roadmap Phase 1）。S(x) 只喂主色路，展示/调制永远用
A(x)（`ncut_color` 默认开，`--no-ncut-color` 回退；mock 无特征恒等注意力）。

- 代码：`perception/`（`base.py` 后处理与双图接口 / `mock_backend.py` 无权重联调 /
  `ncut.py` 谱分割 / `dinov2_backend.py` 真模型，Phase 1 校验清单见 roadmap）。

### M4 主色计算

两个并行实例只差一个权重：焦点色 w = ramp(S(x))，氛围色 w = ramp(1−S(x))，S =
主色世界图（默认 NCut 谱分割，见 M3；`ncut_color`=false / mock 时 S = A）——与
展示路调制**同形**的双阈值分段线性（同一份 `utils/ramp.py`，所见即所得）：S < lo
（`weight_lo`，默认 0.2）权重记 0、S ≥ hi（`weight_hi`，默认 0.8）记 1、中间线性。
lo/hi 是两个世界分布分离的主杠杆（趋同 → 调大 lo）。
**为什么弃用旧式 w = 1+λ·A**（2026-11-05 定案）：它给背景保底权重 1，而加权质量
∝ 面积×权重——主体占两成画面时 0.2×4 反被 0.8×1.9 碾压，注意力图再对、λ 调到
无穷大也排不掉大面积背景（实测焦点色被背景主导）。权重能压到 0 才是结构性修复。
Mini-Batch K-Means，聚类时使用 Lab 空间（a/b 权重高、L 低——空间选择已由权重完成，
L 不必再兼职掩膜，这正是展示/计算分离的红利）。K 固定（warm-start 的前提），动态
类数放合并层：K-Means 之后把簇心距离 < `merge_dist`（默认 0.10，聚类同空间）的簇
并为一族（族心 = 加权质量均值；贪心合并并用族均值重算距离，链式近邻不会把远簇拖
进来）再统计打分——同色系被 K-Means 拆出的深浅碎片合成一个候选，同色系场景自动
收敛到 2-3 族（2026-11-06 实测反馈"类数偏多"），真多彩场景互距远、不丢分辨率。

权重掩膜在全分辨率上先定（ramp 的 w>0 ⟺ S>lo，只做一次比较），抽样只发生在本世界
像素上、密度按本世界面积自适应：n_world ≤ 预算全取（带内像素一个不漏）、超预算按
本世界面积定步长交掩膜（样本 ≈ 预算，起点随机抖动抗周期走样）——主体占画面小时，
全帧等步长网格会把绝大部分预算漏给零权重背景格点（1080p 下 5% 主体旧路径只得 ~600
样本，现路径给满预算），两世界不再互相"饥饿"（2026-11-06）。本世界几乎无合格像素时
（如平坦热图）退化为全帧无权重，保证 10Hz 输出不断流。权重只经 sample_weight 进入
簇心与打分（若采样概率也按权重走，会产生 w² 双重强调）。打分器 v1（Phase 2，按
Itti & Koch 2001 细化）：

  score = 质量 × 彩度 × 紧凑度 × 对比度

- 质量/彩度/紧凑度：v0 遗留，回答"这个簇能不能代表它所在的世界"。彩度系数
  (0.45+0.55c) 特意比其余两项 (0.6+0.4x) 陡——2026-11-05 实测反馈鲜艳度应有略高
  影响力（灰→满彩最大分差 2.2 倍，旧式 1.8 倍）；
- **对比度**（论文 center-surround / 空间竞争的映射；2026-11-06 对齐）：焦点实例
  的基准 = **上一帧氛围主色**（真正的 surround，pipeline 交叉接线传入）——贴背景
  色的候选被打折，"保护色不显眼"（Itti & Koch 的 surround 即背景；生物学同型即
  保护色/伪装：贴环境色的目标不吸引注意）。无参照（首帧/`--no-surround-contrast`
  A/B 对照）退回全帧均色近似。只单向接焦点侧：保护色语义本就只在被注视方，且
  避免双实例互推的反馈环——焦点离背景远了，两路输出自然去趋同；
- **动量化迟滞选主**（注视稳定性的时序类似物；论文的 IOR 方向相反——抑制在位
  赢家强制扫视前进，故不标 IOR）：与动量参考色接近的"在位簇"仅在挑战簇有
  (1 + margin×动量) 分数优势时让位。动量三态：**连胜攒**（赢家贴参考色且本就是
  分数赢家，每帧 +0.2，约 5 帧满——保护力要"攒出来"而非白给）、**被压制挑战者
  慢泄**（挑战者分数更高却被门槛压下 → ×0.85/帧：持续小优势 ~0.5-1s 内夺主。
  此态不可省——泄放若只挂"赢家换人"，而门槛恰恰阻止换人，满动量下小优势挑战
  永无出头之日，门槛自锁，2026-11-06 合成状态机模拟发现）、**换景快泄**
  （赢家远离参考色 → ×0.6 + 参考色跟新赢家）。参考色本身是赢家 Lab 的 MoCo 式
  动量更新（慢 EMA，α=0.3）。margin 默认 0.15→0.10（2026-11-05 实测反馈旧式
  锁死过久）；静态攒满后仍全额抑制同屏近分簇的主色闪烁（M6 管换景，这里管同屏）；
- **warm-start 簇心延续**：上轮簇心作本轮 K-Means 初始化（n_init=1），簇集合时域
  连贯、候选颜色跨帧可比——迟滞选主的前提，静态画面不再每轮从随机状态重聚。

置信度输出为**支配度**（胜者得分 / 全簇得分和），比绝对分可解释且有界，供下游
灯带做淡入淡出依据。

10Hz 实时预算（100ms/轮）：`sample_budget=12000`（8000 时多彩场景统计不稳）、
`kmeans_batch_size=2048`，实测双实例约 21ms/轮（warm-start 后；profile 显示瓶颈
全在 MiniBatchKMeans，Lab 转换可忽略）。

- 代码：`color/dominant.py`。

### M5 双流亮度调制（展示路）

分段线性阈值化（ramp）：焦点流对 A(x) 双阈值——A≤lo 全黑（`black_floor` 残亮）、
A≥hi 原始亮度、中间线性；氛围流对 1−A(x) 同样处理（阈值独立配置）。比旧版 γ
线性更激进：注意力够低就看不见、够高就原样，明暗分离锐利。逐像素乘法，全帧率
跑（用最近热图，与热图更新解耦）。预览窗支持全屏（`f` 键 / `--fullscreen`，
画布 letterbox 补黑边）——演示时观众直接看到两路画面各自强调什么，
**它本身就是这套系统最好的解释图**。

- 代码：`display/modulation.py` + `viz/windows.py`。

### M6 时域稳定与输出

最终输出 `{焦点色RGB, 氛围色RGB, 置信度×2, 时间戳}`；对 10 Hz 色值做 EMA 平滑
（`ema_alpha` 是"每次更新"语义，按 color.hz 调校），**大跳变重置**：新主色与 EMA
状态的 RGB 距离超过 `jump_reset_dist` 时直接置入——EMA 会把场景切换"爬"成一段
错误的中间色相（迟滞管同屏闪烁，重置管换景，二者互补）；留 WebSocket/UDP 外发口子
（将来接灯带/特效，联调工具 `scripts/receiver_demo.py`）。

- 代码：`stability.py` + `output/`（sinks：控制台 / JSONL / UDP / WebSocket）。

## 线程模型（实现层）

采集（30fps）→ 感知（10fps）→ 主色（10Hz）三条工作线程，线程间走"最新者赢"单槽
（`buffers.LatestSlot`），消费方永远拿最新中间结果；显示路在主线程（cv2 GUI 约束），
与计算路零耦合。
